# 体检报告样本(10 份 · 三甲医院体检中心格式)

供 AI 营养师 Agent 联调/演示使用的健康报告样本,格式参照三级甲等医院健康管理中心体检报告:
完整包含**受检者信息 → 一般检查 → 科室检查 → 实验室检查(7 组)→ 影像学与功能检查 → 体检结论与建议**。

## 目录内容

| 文件 | 说明 |
|---|---|
| `report_01~10_*.txt` | 10 份可上传的体检报告(UTF-8) |
| `_generate_reports.py` | 报告生成器(结构化数据 + 版式模板,可改数据重新生成) |
| `verify_reports.py` | 解析校验脚本 —— 用后端真实解析器校验 6 项指标是否被正确抽出 |

## 如何导入

**前端**:登录 → 健康报告 → 上传文件(选择 `report_*.txt`)→ 系统自动抽取文本并解析出指标。
**API**:

```bash
# 1) 上传文件到对象存储(MinIO),拿到 file_key
curl -X POST http://localhost:8080/api/files/upload \
     -H "Authorization: Bearer <token>" -F "file=@report_01_张建国_男52_代谢综合征.txt"
# 2) 用 file_key 建立报告,后端自动抽文本 + 解析
curl -X POST http://localhost:8080/api/health-reports/ \
     -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
     -d '{"report_name":"张建国 体检报告","file_key":"<file_key>"}'
```

> 支持 `.txt` / `.md` / `.pdf`。若用 PDF,文本抽取依赖 `pypdf`,且排版须保证「项目名与结果相邻」。

## 重新生成与校验

```bash
cd sample_reports
python _generate_reports.py     # 重新生成 10 份报告
python verify_reports.py        # 用后端解析器校验,必须 10 通过 / 0 失败
```

## 版式与解析器的关键约束(改报告时务必遵守)

后端的 `health_report_parser.py` 是**正则规则引擎**,对版式敏感,以下约束不是风格问题而是正确性问题:

1. **结果必须紧跟项目名**。正则形如 `尿酸[^\d]{0,12}(\d+)`,允许的间隔上限是 **12 个字符**。
   因此化验单行采用 `项目名 | 结果 | 单位 | 参考范围` 的竖线分隔——若改用宽空格对齐,
   间隔会撑到 20+ 字符,正则匹配失败,指标直接解析不出来(或错误地在"结论"里抓到别的数字)。
2. **血脂四项顺序固定为 总胆固醇 → 甘油三酯 → HDL-C → LDL-C**。
   正则 `(?:总)?胆固醇` 取**最左匹配**,而 HDL/LDL 名称里也含"胆固醇",顺序颠倒会把 HDL 值当成总胆固醇。
3. **尿常规的 pH 项写「酸碱度(pH)」**,不可写「尿酸碱度」——否则会被"尿酸"正则误吞。
4. **化验单之前的段落**(基本信息/个人史/一般检查/科室检查/影像)
   不得出现 `尿酸/血糖/胆固醇/甘油三酯` 后 12 字符内有数字的写法,
   例如"高尿酸血症病史 5 年"会让正则抓到 5。样本中一律改写成"痛风(2019 年确诊)"这类表述。
5. **结论建议放在化验单之后**(与真实报告顺序一致),此时最左匹配已命中化验单,结论里的数值不会干扰解析。

## 批量 50 份报告(`reports_50/`)

除上方 10 份样例外,本目录另含 `reports_50/` **统一路径**下的 **50 份**三甲医院标准体检报告,用于批量演示、压测与联调。所有 50 份集中存放于同一目录,便于一次性选择上传。

- **统一路径**：`sample_reports/reports_50/`(全部 50 份 `.txt` 集中在一个目录)
- **生成器**：`generate_50.py` —— 复用 `_generate_reports.py` 的版式引擎与 `LAB_ITEMS/PANELS`,定义 18 个临床场景模板(正常对照 + 17 类异常)与 50 个受检者(persona),版式约束与上方完全一致。
- **校验器**：`verify_50.py` —— 用后端真实解析器 `HealthReportParser` 逐份解析,断言 6 项核心指标抽取值 == 设计值、指标数 == 5,并统计正常/异常份数。

```bash
cd sample_reports
python generate_50.py     # 重新生成 50 份到 reports_50/
python verify_50.py        # 后端解析器校验,须 50 通过 / 0 失败
```

**分布**(覆盖解析器全部等级分支):

| 类型 | 份数 | 说明 |
|---|---|---|
| 正常对照 | 10 | 各项指标均在参考范围内(异常项 0) |
| 异常报告 | 40 | 代谢综合征、2 型糖尿病+高血压、高尿酸血症、空腹血糖受损、高甘油三酯+脂肪肝、高胆固醇(绝经后)、甲减、甲亢、缺铁性贫血、骨质疏松、颈动脉斑块、慢性肾病、肾结石、肥胖代谢、高血压2级+左室肥厚、痛风极高危 |

异常项分级覆盖:血压 偏低 / 正常 / 正常高值 / 1 级 / 2 级;血糖 正常 / 空腹血糖受损 / 疑似糖尿病;
尿酸 正常 / 偏高 / 显著偏高;总胆固醇 正常 / 边缘升高 / 升高;甘油三酯 正常 / 边缘升高 / 升高。

> 统一路径下的文件名格式:`report_XX_姓名_性别年龄_场景标签.txt`(XX 为 01~50 连续编号)。
